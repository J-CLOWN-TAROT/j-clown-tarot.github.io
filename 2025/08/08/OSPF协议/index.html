    2.ospf 术语

    ① 区域

    一.

    区域尽管我们自己设置的时候一般使用证书，但是实际表示的是一个类似 IP 的结构

    area 0  ==  area 0.0.0.0
area 1  ==  area 0.0.0.1

    这里最大可以到 255.255.255.255，也就是 4,294,967,296

    因此这里的 area ID 实际上只是整数的一种表示方式

    二.

    area 0 是骨干区域，其余区域都是非骨干区域，并且所有非骨干区域到要与骨干区域相连

    ②Router-ID

    系统自动配置

    遵循原则：首先查看回环口，选择回环口中最大的 IP 作为 route ID -> 如果未配置回环口，则选择物理接口的最大值

    但是，在eNSP的华为设备中，实际上是谁先被设置，谁就作为route ID

    5.邻接关系建立

    通常在一个 ospf 域内，只要能够接收到 hello 包，则两者为邻居关系；而如果建立了相同的数据库，怎转变为邻接关系

    邻接关系建立流程

    OSPF 邻接状态机概览

    OSPF 邻接状态机有以下几个主要状态：

    1. Down：邻居关系未建立。
    2. Init：收到了对方的 Hello 包，但没有双向确认。
    3. 2-Way：双向确认，说明可以开始进行进一步的邻接建立。
    4. ExStart：决定谁是主路由器，谁是从路由器，协商初始化。
    5. Exchange：交换数据库摘要（DD 报文）。
    6. Loading：加载缺失的 LSA（请求和更新）。
    7. Full：邻接关系完全建立，LSDB 完全同步。
    状态转换和对应报文
    1. Down → Init
    • 状态说明：这表示还没有收到对方的 Hello 包。
    • 报文：
      • 路由器发送 Hello 包，它是 OSPF 邻接的开始。
      • 在收到对方的 Hello 包后，路由器进入 Init 状态。
    2. Init → 2-Way
    • 状态说明：在这个状态，路由器已经收到了对方的 Hello 包，但此时 单向 看到对方，双向确认 没有完成。
    • 报文：
      • 对方发送的 Hello 包 包含其 Router ID，目标是与路由器建立联系。
      • 在此阶段，路由器会通过 Hello 包 相互确认，在每个 Hello 包里会带上双方的 Router ID。
      • 双方交换完 Hello 后，如果 Hello 包中的 Router ID 彼此都在对方的 Hello 包中（即双向确认），状态会变为 2-Way。
    3. 2-Way → ExStart
    • 状态说明：在 2-Way 状态下，双方确认了彼此的身份，可以开始协商交换数据库的顺序。
    • 报文：
      • 在 ExStart 状态下，双方会发送 空DD（Database Description）报文 来决定数据库交换的顺序。
      • 交换的内容包括：
        • OSPF 的 Router ID（决定谁是主路由器，谁是从路由器）
        • 交换的数据块（LSA 的头部）
      • 主从协商：通过比较 Router ID，选出 主路由器（Master）和 从路由器（Slave）。
    4. ExStart → Exchange
    • 状态说明：主路由器与从路由器在 ExStart 阶段达成共识，开始交换链路状态摘要（LSA）。
    • 报文：
      • 交换 DD（Database Description）报文。
      • 该报文仅包含 LSA 的 摘要信息，即 LSA 类型、序列号 等，用来比较双方数据库的差异。
      • 交换的目的：确认自己数据库中是否缺失对方的 LSA。
    5. Exchange → Loading
    • 状态说明：当路由器发现自己有缺失的 LSA 时，开始进入 Loading 状态，向对方请求缺失的 LSA。
    • 报文：
      • LSR（Link State Request）：如果某些 LSA 没有在 DD 报文 中找到，路由器会发送 LSR 报文请求缺失的 LSA。
      • LSU（Link State Update）：对方收到 LSR 后，会回复 LSU，携带完整的 LSA 数据，进行数据交换。
    6. Loading → Full
    • 状态说明：当路由器完成了所有需要的 LSA 交换，并且数据库完全同步后，进入 Full 状态。
    • 报文：
      • LSAck（Link State Acknowledgment）：在 Loading 阶段，收到 LSU 后，路由器会发送 LSAck 确认接收到 LSA。
      • 这一阶段表示 OSPF 邻接关系完全建立，数据库同步完成。
